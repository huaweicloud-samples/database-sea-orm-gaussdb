## 二、类型定档

- `information_schema.columns`：`number(10,2)` → data_type `numeric`；`varchar2` → `varchar`；`clob`/`blob`/`raw` → **同名私有 udt**；`date` → **`datea` 私有 udt**（Dapper/prisma 定档复现）。
- **`date` 列拒收 ISO 文本**：`'2026-10-21'` 报 `22007: invalid value "26-10-21" for "MON"`——要求 Oracle `DD-MON-RR` 形态（Prisma 定档复现）。业务引导用 `timestamp`。
- 空串→NULL：`INSERT ''` 后 `IS NULL = true`，实锤。

## 六、sqlx 0.9 侧定档（P0 详细版，2026-10-21）

工具：`probe/sqlx-probe/`（sqlx 0.9.0 + tokio，rsproxy 拉取），探针库 seaorm_survey，密码走环境变量。

### [1] 连接与认证

- **MD5 认证 + PgPool 建池：OK**（`password_encryption_type=1` 下 sqlx 0.9 直连成功）。
- `server_version` 返回 9.2.4 假象：**sqlx 连接期不受影响**（未拒绝连接、未降级报错）。

### [2] 扩展协议 PL/SQL（关键分歧点）

- `CREATE OR REPLACE FUNCTION ... $$ BEGIN NULL; END $$ LANGUAGE plpgsql` 经 sqlx 0.9 **执行成功**（[3a] OK，函数可调用）。
- **与 Dapper（Npgsql）定档不同**：Npgsql 扩展协议 Parse 阶段按分号截断必炸 42601；sqlx 0.9 的 prepared statement 路径不复现此问题。
- **结论：sqlx 侧无需 PL/SQL 截断补丁**；sea-orm migration 中可经 sqlx 执行含体内分号的 PL/SQL DDL（仍建议 P2 再验一个含多条语句/更复杂体的用例）。

### [3] IDENTITY（sea-orm 2.0 默认自增形态）

- `CREATE TABLE (id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, ...)`：**OK**。
- `INSERT ... RETURNING id`：**执行成功，但 id 列被服务端报告为 `NUMERIC` 而非 INT4** —— Rust 侧 `i32` 解码被拒
  （`Rust type i32 (as SQL type INT4) is not compatible with SQL type NUMERIC`）。
- `RETURNING id::text` 通道 OK（取到自增值）。
- **影响 sea-orm 适配**：自增主键 `last_insert_id` 的解码需按 NUMERIC/TEXT 通道适配（A 模式 number 语义渗透进 identity）。

### [4] floatvector wire 行为（OID 4409）

| 用例 | 结果 |
|---|---|
| RowDescription 类型名 | sqlx 正确识别 `type_info.name = "floatvector"` |
| 直读列为 String | 拒（`TEXT is not compatible with SQL type floatvector`，严格 OID 检查） |
| `repr::text` 读 | **OK**（`[1,2,3]`） |
| `bind(String)` 直插 | 拒：`column "repr" is of type floatvector but expression is of type text`（sqlx 把参数声明为 text OID，服务端不隐式转换——与 psycopg2 发 untyped 参数不同） |
| `repr <-> $1`（bind String） | 拒：`operator does not exist: floatvector <-> text` |
| **`$1::floatvector` 显式 cast 插入** | **OK** |
| **`repr <-> $1::floatvector` ANN 排序** | **OK** |
| round-trip（cast 插入 → ::text 回读） | **OK**（`[7.5,8.5,9.5]`） |
| pg_type | oid=4409、typinput=vector_in（与 psycopg2 侧一致） |

- **结论：floatvector 走「文本传输 + 显式 cast」通道完全可行**。sea-orm 侧两条实现路径：
  a. SQL 生成侧统一追加 `::floatvector` cast（sea-query gaussdb 方言）；
  b. 自定义 `Encode`（`PgTypeInfo::with_oid(4409)` 声明参数类型）——更干净，留给 gaussdb-vector 特性。

### [5] 附带发现：sqlx 0.9 SqlSafeStr API

- `sqlx::query()` 签名为 `sql: impl SqlSafeStr`（仅 `&'static str` 字面量与 `AssertSqlSafe` 包装满足）——0.9 的防注入 API 变化。
- sea-orm 2.0.4 已适配此体系（其动态 SQL 调用点应有对应处理）；适配中新增代码需遵循同一模式。
