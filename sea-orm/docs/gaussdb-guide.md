# SeaORM GaussDB 业务接入指南

> 基于 SeaORM 2.0.4 / GaussDB Kernel 507.0.0（集中式 / A 兼容，`DBCOMPATIBILITY = 'A'`）真库实测定档（2026-10-26）。
> 差异定档与症状速查见根目录 `GAUSSDB.md`；测试方法见 `docs/gaussdb-testing.md`。本指南面向业务开发者。

## 1. 安装

fork 未发 crates.io，使用 git 依赖 + fork patch（`gaussdb` feature 依赖 `sea-query/backend-gaussdb`，
该 feature 仅存在于 sea-query fork 分支，必须 patch）：

```toml
[dependencies]
sea-orm = { git = "https://github.com/<fork-org>/sea-orm", branch = "gaussdb-adapter",
            features = ["gaussdb", "runtime-tokio-native-tls"] }
# 业务需要向量类型时（gaussdb 的超集别名）：
# features = ["gaussdb-vector", "runtime-tokio-native-tls"]

[patch.crates-io]
sea-query = { git = "https://github.com/<fork-org>/sea-query", branch = "gaussdb-backend" }
sea-query-sqlx = { git = "https://github.com/<fork-org>/sea-query", branch = "gaussdb-backend" }
# 使用 schema-sync / sea-orm-cli / 迁移时再补：
# sea-schema = { git = "https://github.com/<fork-org>/sea-schema", branch = "gaussdb-discovery" }
```

`gaussdb` feature 不含 runtime，与上游 feature 体系同构，需叠加
`runtime-tokio-native-tls` / `runtime-tokio-rustls` 等。

## 2. 连接与连接池

```rust
use sea_orm::Database;

let db = Database::connect("gaussdb://appuser:<PASSWORD>@localhost:5432/mydb").await?;
// 集中式部署建议（PG 驱动参数，sqlx-postgres 支持待验证）：
// "gaussdb://appuser:<PASSWORD>@host:5432/mydb?targetServerType=master"
```

- URL scheme 为 `gaussdb://`；底层复用 PostgreSQL 连接栈（sqlx-postgres wire 协议），
  `ConnectOptions` 的 PG 选项（连接池大小、`application_name`、`statement_timeout`、
  `schema_search_path` 等）照常可用。
- **MD5 部署要求**：服务端 `password_encryption_type = 1` + `gs_hba.conf` 放行 md5。
  云上生产默认 sha256（华为私有）当前不支持。
- **opfusion 说明**：GaussDB 的 SQL bypass 执行器对「参数化 PBE + 非 0 result formats」组合有内核
  断言缺陷（29003），SeaORM 的 prepared statements 正常路径即可踩中。GaussDB connector 建池时已
  统一追加连接级 `enable_opfusion=off` 规避（标准执行器无此限制）——**用户无需任何操作**，
  了解原因即可，勿手工改回。
- 服务端 `server_version` 恒报 9.2.4（假象），勿据此做特性探测。

## 3. 实体定义与 CRUD

标准 SeaORM 2.0 实体写法在 GaussDB 上直接可用（`#[sea_orm::model]` + `DeriveEntityModel`，
强类型列 `COLUMN`、ActiveModel builder、Entity Loader 等）：

```rust
mod cake {
    use sea_orm::entity::prelude::*;

    #[sea_orm::model]
    #[derive(Clone, Debug, PartialEq, DeriveEntityModel)]
    #[sea_orm(table_name = "cake")]
    pub struct Model {
        #[sea_orm(primary_key)]           // 渲染为 integer GENERATED BY DEFAULT AS IDENTITY
        pub id: i32,
        pub name: String,
    }

    impl ActiveModelBehavior for ActiveModel {}
}

let inserted = cake::ActiveModel { name: Set("Apple Pie".into()), ..Default::default() }
    .insert(&db).await?;   // 自增主键回填已适配（A 模式 RETURNING 报 NUMERIC，解码兜底 i32/i64）
```

GaussDB 注意事项：

- **upsert（已自动改写）**：`.on_conflict(...)` 在 GaussDB 后端渲染为
  `ON DUPLICATE KEY UPDATE`（DO UPDATE 支持 `excluded.col`）。DO NOTHING 语义由非键列自赋值
  模拟；表无可用非键列（如仅主键单列表）时会显式报错——避免单列表 upsert。
- **空字符串 → NULL**：写入 `''` 回读 NULL（Oracle 语义），判空逻辑用 `IS NULL` 口径。
- **date 列引导**：`date` 类型拒收 ISO 文本（要求 `DD-MON-RR`），直读返回引导错误；
  建模请用 `timestamp`（`DateTime`/`NaiveDateTime` 直读直写均通）。
- **IDENTITY 序列**：`DROP TABLE` 不会级联删除附属序列 `{table}_{col}_identity`；
  手工清表后重建请补 `DROP SEQUENCE IF EXISTS ...`（迁移 down 已内置处理，见 §5）。
- `in (...)` 的数组绑定参数请改用 `= any(...)` 形态；`LATERAL` / 聚合 `FILTER` 会被能力门
  拒绝（见 §7）。

## 4. 实体生成（sea-orm-cli）

从 fork 安装 CLI（`gaussdb` feature）：

```bash
git clone -b gaussdb-adapter https://github.com/<fork-org>/sea-orm
cd sea-orm/sea-orm-cli
cargo install --path . --features gaussdb
```

生成实体（`gaussdb://` 直接分派，复用 postgres discovery 链路）：

```bash
sea-orm-cli generate entity -u "gaussdb://appuser:<PASSWORD>@localhost:5432/mydb" -o out
```

真库端到端验证过的类型映射：identity 主键 → `i32`；`number` → `Decimal`；
`varchar2` / `clob` → `String`；`blob` / `raw` → `String`（hex）；`timestamp` → `DateTime`；
`floatvector` → `String`（custom，可按 §6 包装为 `FloatVector`）。
identity 语义经 `pg_attribute.attidentity` 通道识别（A 模式 `is_identity` 恒为 NO）。

## 5. 迁移

sea-orm-migration 已带 `gaussdb` feature（透传 sea-orm/gaussdb 与 postgres schema 探针）：

```toml
[dependencies]
sea-orm-migration = { git = "https://github.com/<fork-org>/sea-orm", branch = "gaussdb-adapter",
                      features = ["gaussdb", "runtime-tokio-native-tls"] }
```

```rust
// Table::create 的 auto_increment() 在 GaussDB 后端渲染为
// integer GENERATED BY DEFAULT AS IDENTITY —— A 模式可用（临时表才禁 serial）
manager.create_table(
    Table::create().table(MyT::Table).if_not_exists()
        .col(ColumnDef::new(MyT::Id).integer().not_null().auto_increment().primary_key())
        .col(ColumnDef::new(MyT::Name).string_len(64).not_null())
        .to_owned(),
).await?;
```

**序列清理注意事项**：A 模式 IDENTITY 附属序列不随 `DROP TABLE` 级联删除，残留序列会让重建表
报 42P07。自写迁移的 `down()` 里 DROP TABLE 之后请补：

```rust
manager.get_connection()
    .execute_unprepared("DROP SEQUENCE IF EXISTS my_t_id_identity").await?;
```

`seaql_migrations` 迁移记录表在 GaussDB 上读写正常（opfusion 规避见 §2）。

## 6. 向量能力（floatvector）

前提：GUC `enable_vectordb = on`；建表 `repr floatvector(3)`。

```rust
use sea_orm::{ConnectionTrait, DbBackend, Statement, FloatVector};

let vec = FloatVector(vec![1.5, 2.5, -3.25]);

// 写：文本形态绑定 + SQL 侧 $1::floatvector 显式 cast（服务端拒收 TEXT 声明参数，定档形态）
db.execute_raw(Statement::from_sql_and_values(
    DbBackend::GaussDB,
    "INSERT INTO vt (id, repr) VALUES ($1, $2::floatvector)",
    [1i32.into(), vec.clone().into()],
)).await?;

// 读：query_all_raw / query_one_raw 后 try_get_by（binary 解码已内置）
let rows = db.query_all_raw(Statement::from_string(
    DbBackend::GaussDB, "SELECT repr FROM vt WHERE id = 1".to_owned())).await?;
let back: FloatVector = rows[0].try_get_by("repr")?;

// ANN：ORDER BY repr <-> $1::floatvector LIMIT k（<-> 为 L2 距离，参数绑定实测可用）
let nearest = db.query_one_raw(Statement::from_sql_and_values(
    DbBackend::GaussDB,
    "SELECT id FROM vt ORDER BY repr <-> $1::floatvector LIMIT 1",
    [query_vec.into()],
)).await?;

// 距离函数：l2_distance / cosine_distance / inner_product（与 pgvector 同名不同型）
// SELECT l2_distance(repr, $1::floatvector)::float8 AS d FROM vt ...
```

接入 `DeriveEntityModel` 的业务侧最小路径（本期不内置向量列一等支持）：

```rust
#[derive(Clone, Debug, PartialEq, sea_orm::DeriveValueType)]
pub struct Repr(pub FloatVector);
```

GSIVFFLAT 索引（适用 1 万~200 万行；更大规模用 GsDiskANN）：

```sql
CREATE INDEX vt_repr_idx ON vt USING GSIVFFLAT (repr L2) WITH (IVF_NLIST = 16);
-- 查询 GUC：gsivfflat_probes 建议 = ivf_nlist 的 10%
-- 运维：gs_ivfflat_inspect('vt_repr_idx')；数据变更 >20% 或 truncate 后建议重建
```

约束：元素不支持 NaN/Inf/NULL（22000）；**boolvector 列内核级拒 NULL**（0A000），本期未实现
boolvector 类型通道；floatvector 列整列可为 NULL。

## 7. 能力门说明（LATERAL / FILTER）

GaussDB A 模式对以下语法以 42601 拒绝执行。能力门在 SQL 出进程前拦截，返回
`DbErr::BackendNotSupported` 并附重写指引（覆盖 raw SQL / 查询构造器 / 迁移全部出口）：

- `LATERAL join is not supported by GaussDB A-mode (server reports 42601);
  rewrite the query as a correlated subquery`
- `aggregate FILTER (WHERE ...) clause is not supported by GaussDB A-mode
  (server reports 42601); rewrite it as CASE WHEN inside the aggregate or as a filtered subquery`

重写建议：LATERAL 改相关子查询；聚合 `FILTER (WHERE ...)` 把 `CASE WHEN` 放进聚合内部或改
过滤子查询。误报仅可能来自恰好包含上述 token 的字符串字面量（保守方向：多拒不漏放）。
